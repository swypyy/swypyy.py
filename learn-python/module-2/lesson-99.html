Comments in Python

Learn how to write comments, explain your code, temporarily disable statements, and document Python functions clearly.

1. What Are Comments?

Comments are notes written inside a program to explain what the code does. They are meant for people reading the code, not for Python to execute.

Python ignores comments when running a program. Comments can help you remember why you wrote something and help other developers understand your work. 

# This program displays a welcome message
print("Welcome to Python!")
OUTPUT
Welcome to Python!

The line beginning with # is a comment. Only the print() statement produces output.

Remember: Comments do not change what a program does. They explain the program to the people reading it.

2. Writing Single-Line Comments

In Python, a single-line comment begins with the hash symbol #. Everything after that symbol on the same line is treated as a comment, unless it is inside a string. 

# Store a student's name
name = "Anu"

# Store the student's age
age = 16

# Display the information
print(name, age)
OUTPUT
Anu 16

Commenting out a statement

You can temporarily prevent a line of code from running by placing # at its beginning. This is called commenting out code. 

print("This line runs")

# print("This line does not run")

print("This line also runs")
OUTPUT
This line runs
This line also runs

3. Writing Inline Comments

An inline comment appears on the same line as a statement. It begins after the code. 

age = 16  # Student's age
total = 100 + 50  # Calculate the total

print(age)
print(total)
OUTPUT
16
150

Inline comments are useful when a short explanation is needed for a particular statement.

Good practice: Keep inline comments short and leave enough space between the code and the comment so the line stays readable.

4. Can Python Have Multi-Line Comments?

Python does not have a separate special symbol for a block comment. A common approach is to write several single-line comments, each beginning with #. 

# This program calculates the area
# of a rectangle using its length
# and width.

length = 10
width = 5

area = length * width

print(area)
OUTPUT
50

This is the recommended way to write ordinary multi-line comments in Python.

5. Triple Quotes and Their Purpose

Python supports triple-quoted strings using either three single quotes or three double quotes. 

message = """Python is easy to read.
It is used in many fields.
It is useful for beginners."""

print(message)
OUTPUT
Python is easy to read.
It is used in many fields.
It is useful for beginners.

Triple quotes create a string that can span multiple lines. They are not technically comments.

Important distinction: Triple-quoted text is still a string. If it is not assigned to a variable or used as a docstring, it may simply be an unused string expression. Use # for normal comments.

6. Understanding Docstrings

A docstring is a string used to document a module, function, or class. It is usually written immediately after the definition.

Docstrings help explain what a function or class is designed to do. Python makes them available through the object's __doc__ attribute.

Function docstring example

def greet():
    """Display a welcome message."""
    print("Welcome!")

greet()
OUTPUT
Welcome!

Reading a docstring

def add(a, b):
    """Return the sum of two numbers."""
    return a + b

print(add.__doc__)
OUTPUT
Return the sum of two numbers.

You will learn more about functions and documentation in the Functions and Modules module.

7. Comments Inside a Program

Comments can explain different parts of a program. Here is a complete example of a simple marks calculator. 

# Store marks for three subjects
maths = 85
science = 90
english = 80

# Calculate total marks
total = maths + science + english

# Calculate average marks
average = total / 3

# Display the results
print("Total:", total)
print("Average:", average)
OUTPUT
Total: 255
Average: 85.0

The comments divide the program into clear steps: storing values, calculating results, and displaying information.

8. Good Commenting Practices

Comments should make code easier to understand. Writing too many unnecessary comments can make a program harder to read.

Explain why, not just what

A useful comment often explains the reason behind a decision rather than repeating the code. 

# Less useful: repeats what the code says
# Add 10 to score
score = score + 10

# More useful: explains why the value changes
# Award bonus points for completing the challenge
score = score + 10

Keep comments accurate

If you change your code, update any comments that no longer describe it correctly.

Use clear language

  • Write comments that are easy to understand.
  • Keep explanations short and relevant.
  • Avoid comments that repeat obvious code.
  • Do not leave outdated explanations.
  • Use docstrings to document functions and classes.

Remember: Good code should be understandable. Comments should add useful information instead of creating unnecessary noise.

9. Common Commenting Mistakes

Mistake 1: Forgetting the # symbol

# Incorrect
This is a comment

# Correct
# This is a comment

Without the hash symbol, Python tries to interpret ordinary text as code and may raise a syntax error.

Mistake 2: Using comments to hide important code

Commenting out code temporarily is useful while testing, but old unused code should not be left scattered throughout a finished program.

Mistake 3: Writing comments that repeat everything

# Bad: the comment repeats the statement
age = 16  # Set age to 16

# Better: explain something useful
age = 16  # Age used for the eligibility check

Mistake 4: Treating every triple-quoted string as a comment

Triple-quoted strings are strings, not ordinary comments. Use them for docstrings or actual multi-line string data.

12. Lesson Summary

In this lesson, you learned how to document Python programs using comments and docstrings.

  • # starts a single-line comment.
  • Comments are ignored when Python executes code.
  • Inline comments appear beside statements.
  • Use multiple # lines for ordinary multi-line comments.
  • Triple-quoted strings can create multi-line strings.
  • Docstrings document modules, functions, and classes.
  • Good comments explain useful details without repeating obvious code.

Key takeaway: Comments make programs easier for people to understand and maintain. Write them clearly, keep them accurate, and use docstrings when documenting functions and classes.
